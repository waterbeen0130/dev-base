# 시멘틱 변환

> 이 문서는 objective.md의 상세 참조 문서입니다.
> 관련 DoD: DOD-004, DOD-005

## 개요

정규화 엔진이 출력한 중간 JSON을 AI가 읽고, 시멘틱 HTML 구조와 최종 CSS를 생성하는 2차 파이프라인. 1차에서 "값"이 확정되었으므로, 2차에서는 "의미 부여"(태그 선택, 구조 판단, 클래스 네이밍)에만 집중한다.

## 설계 결정

### AD-003: 2단계 파이프라인 아키텍처
- **결정**: 1차 기계적 정규화(규칙 기반) → 2차 AI 시멘틱 변환
- **근거**: AI 해석 편차의 원인이 raw JSON 해석에 있으므로, 값 확정(1차)과 의미 부여(2차)를 분리. 1차 결과물만으로도 값의 정확성 검증 가능
- **대안 검토**: 단일 파이프라인(AI가 raw JSON에서 바로 최종 코드 생성) — 기각: 현재 문제의 근본 원인
- **영향 범위**: AI 프롬프트 설계, 검증 체계, 에이전트 브리프 구조

## 상세 명세

### 1. 2차 변환에서 AI가 판단할 영역

1차 정규화에서 CSS 값은 이미 확정. AI는 아래만 판단:

| 판단 영역 | 입력 (중간 JSON) | AI 결정 | 규칙 기반 제약 |
|-----------|-----------------|---------|---------------|
| **HTML 태그 선택** | `tag_hint`, `text.content`, `text.char_length`, `text.has_newline` | `<h2>`, `<span>`, `<p>`, `<ul><li>` 등 | rule_engine.json `text_tag_selection` 규칙 준수 |
| **DOM 구조 결정** | 트리 구조, 반복 패턴 | wrapper div 배치, 리스트화 | max_dom_depth: 5, inner_wrapper_limit: 1 |
| **클래스 네이밍** | 노드 이름, 페이지 컨텍스트 | `{page}_{role}` 패턴 | snake_case, 페이지 프리픽스 필수 |
| **셀렉터 전략** | DOM 구조 | 부모+태그 vs 개별 클래스 | 개별 클래스 최소화 (부모+태그 우선) |
| **반응형 처리** | 레이아웃 정보 | 미디어쿼리 분기점 | breakpoints: [1400, 1200, 960, 768] |

### 2. AI가 판단하지 않는 영역 (1차에서 확정)

- font-size, font-weight, line-height, letter-spacing 값
- color, background-color 값
- padding, margin, gap 값
- border, border-radius 값
- flex-direction, justify-content, align-items 값
- 텍스트 오버라이드 세그먼트 분할 및 각 세그먼트의 스타일

### 3. 태그 선택 규칙 (rule_engine.json 기반)

```
기본 태그: <span>

<p> 사용 조건 (하나라도 충족 시만):
  - node.characters에 \n 포함
  - 텍스트 길이 95자 초과
  - 문장형 마침표/종결어 반복

<h1>~<h6> 사용 조건:
  - 실제 섹션 제목에만 사용
  - 순차적 계층 유지

<ul><li> 변환 조건:
  - 같은 구조의 반복 아이템 2개 이상

절대 금지:
  - 짧은 라벨/키워드에 <p>
  - <figure>/<figcaption> 사용
  - <main>, <article> 남용
```

### 4. CSS 출력 규칙

AI가 최종 CSS를 생성할 때 준수해야 할 포맷:

```
셀렉터 포맷:
  - 각 셀렉터 규칙은 한 줄: .hero_title{font-size:1rem; font-weight:700; color:#090944;}
  - 같은 셀렉터 중복 선언 금지 — 하나로 합침
  - 모든 요소에 개별 클래스 부여 금지 — 부모+태그 선택자 우선

미디어쿼리 포맷:
  @media screen and (max-width: 768px){
  .hero_title{font-size:14px;}
  .hero_desc{font-size:12px;}
  }
  - 내부 규칙은 줄바꿈 분리, 들여쓰기 없음

색상: hex 전용 (#fff, #090944). 투명도 필요 시만 rgba()
레이아웃: flexbox 전용. CSS Grid 금지
border-radius: 원형 50%, pill 2em. 999px 금지
```

### 5. 시멘틱 변환 파이프라인 흐름

```
[정규화된 중간 JSON]
       ↓
[AI 시멘틱 분석]
  - 트리 구조 → DOM 구조 결정
  - 텍스트 노드 → 태그 선택
  - 반복 패턴 → 리스트화
  - 네이밍 → 클래스 생성
       ↓
[HTML 생성]
  - 1:1 노드 매핑 (visible 노드만)
  - 오버라이드 세그먼트 → <span> 분할
  - divider 노드 보존
  - 이미지 → img_area 래핑
       ↓
[CSS 생성]
  - 중간 JSON의 CSS 값을 그대로 사용
  - 셀렉터 전략만 AI가 결정
  - 프로젝트 규칙 포맷 적용
       ↓
[최종 HTML + CSS]
```

### 6. AI 프롬프트에 포함할 규칙 주입

2차 변환을 수행하는 AI(gemini-dev 또는 claude-dev)에게 전달할 핵심 지시:

```
1. 중간 JSON의 CSS 값을 수정하지 마라 — 그대로 사용
2. 태그 선택만 판단하라 (tag_hint를 참고하되 최종 결정은 규칙 기반)
3. DOM 구조는 Figma 트리를 따르되, max depth 5 제한
4. 클래스명은 {page}_{role} 패턴, snake_case
5. 셀렉터는 부모+태그 우선, 개별 클래스 최소화
6. 반복 아이템은 <ul><li>로 변환
7. 짧은 텍스트에 <p> 금지
```

### 7. 품질 기준 — "디자인과 거의 동일" 판정

DOD-005의 구체적 검증 방법:

1. **구조 일치**: Figma 노드 트리와 HTML DOM 구조가 1:1 매핑
2. **값 일치**: 모든 CSS 값이 Figma 원본 속성과 일치 (정규화 엔진이 보장)
3. **시각 일치**: 브라우저 렌더링 결과가 Figma 디자인과 시각적으로 동일
4. **텍스트 일치**: 텍스트 내용, 스타일 오버라이드, 줄바꿈이 모두 보존
5. **이미지 일치**: 모든 이미지가 올바른 위치에 올바른 크기로 배치

## Q&A 보강 사항

- 사용자가 "2차로 AI가 재해석해서 시멘틱한 마크업으로 변경"을 제안 → 1차(값 확정)와 2차(의미 부여) 분리가 사용자의 원래 아이디어
- 최종 목표는 "사람이 세밀 비교작업도 필요없을 정도" → 1차 정규화 품질이 핵심, 2차는 구조적 판단만
- "추출된 코드를 기반으로 상세작업은 인간이 진행" → 2차 변환 결과물이 인간 작업의 시작점이 됨
