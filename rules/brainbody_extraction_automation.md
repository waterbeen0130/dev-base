# 브레인바디 랜딩 추출 자동화 규칙 (지속 반영)

해당 규칙은 `figma_grinmall_brianbody_260212_page.json` 기반 브레인바디 랜딩 추출 시
반복 재현을 위해 고정으로 적용할 최소 규칙이다.

## 1) 텍스트 노드 처리

### 1-1. 태그 판정
- `p`를 기본값으로 두지 않는다.
- `p`는 다음 중 하나일 때만 허용한다.
  - `characters`에 `\n`이 존재 (`<br>` 유지)
  - 문장성/설명형으로 분류 가능한 긴 텍스트
  - 종결어 중심 문장(`습니다`, `됩니다`, `필요합니다`, `있습니다` 등)
- 짧은 라벨/브랜딩 텍스트는 기본적으로 `span`.
- `heading 1~6` 키워드 또는 폰트 크기/가중치 조합이 제목 수준이면 `h1~h6`.

### 1-2. 라벨 패턴 예시
- `브레인바디`, `BrainBody`, `MRI`, `그린몰`, `영상의학과`, `원스톱 토탈케어` 등은 inline span 우선.
- 설명형 문장(문단)은 오직 실제 문맥에서만 `p`로.

### 1-3. 오버라이드
- `characterStyleOverrides` / `styleOverrideTable`는 기존 규칙(`common.md`)의 누적 병합을 준수한다.
- 누락 속성은 직전 구간 스타일을 상속한다.

## 2) 클래스/셀렉터 정책

- 구조 클래스 폭증을 피하고 아래 조합을 우선한다.
  - 최상위 블록: `brainbody_*` 계열
  - 내부 텍스트: `.title`, `.value`, `.text` 같은 의미 단위
  - 위치/상태는 필요할 때만 하위 클래스 추가
- 동일한 의미를 반복하면 자식 선택자(`.card .title`, `.card .value`)로 통합한다.
- `nth-child`는 의미 클래스가 없을 때만 임시로 사용.

## 3) 레이아웃 정합성

- 동일 부모에서 `y` 정렬이 같고 높이가 유사한 박스는 `grid` 또는 `inline-flex`로 한 줄 정렬을 우선한다.
- 가로 폭이 큰 컨테이너는 기본 고정 width 대신:
  - `max-width: <Figma width>px`
  - `margin: 0 auto`
  - 필요 시 `width: min(100%, ...)` 패턴
- 불필요한 `width:100%`는 제거하고, 블록 특성을 중복 지정하지 않는다.

## 4) 라인 하이트/색상/배경 정리

- `line-height`는 동일 단위를 유지하기 어렵거나 반응형 요구가 큰 경우
  - `line-height / font-size` 비율(`1.x`)로 우선 작성.
- `background-color`는 실제 배경 레이어(`SOLID`, 이미지 하단 패널, 명시적 shape)에서만 사용.
- 스타일 병합 후 실제 렌더 결과와 다르면 즉시 규칙 보강한다.

## 5) 후처리 QA 체크리스트 (반드시 자동화 후 실행)

- `BrainBody`, `MRI` 등 중요한 라벨 폰트/색상/강조치가 원본 텍스트와 1:1인지
- `p`/`span`/`h*` 배치가 원본 구조와 동일한지
- 동일 y축 카드/아이템 정렬이 세로가 아닌 행 구조인지
- 블록 폭이 화면 축소 시 `max-width`를 통해 가운데 정렬되는지
- `line-height`와 `background-color`의 과다/부족 선언이 없는지

## 6) 자동화 배포 메모

- 이 규칙은 `generate_html_from_figma.py`의 텍스트 분류 로직과 결합할 때 효과가 크다.
- 추출 결과를 팀 공유 문서화할 때, 클래스 정합성과 텍스트 판정 변경 사유는 별도 로그로 남긴다.
